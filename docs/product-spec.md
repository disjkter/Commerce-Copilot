# 产品需求 v0.1

## 用户问题

用户在购物过程中往往把多个目标放进一句话，例如“推荐一款通勤耳机，并告诉我昨天的订单能不能退”。单一流水线容易混淆商品事实与售后规则，也难以定位失败环节。

## 产品目标

Commerce Copilot 将同一轮输入拆成相互隔离的领域任务，并行取得结果后统一回复。第一版覆盖：

- 商品发现：识别品类、预算和偏好，随后连接本地商品目录。
- 购买后服务：识别订单、物流、退换货等诉求，随后连接只读订单与规则工具。
- 普通咨询：处理问候、能力介绍和需要澄清的问题。

## 非目标

- 不代替用户支付、退款或修改订单。
- 不把演示数据描述成真实平台数据。
- 不在缺少证据时生成确定性的商品、订单或政策事实。

## 可验收标准

1. 单领域请求只运行一个领域 Agent。
2. 混合请求可并发运行多个 Agent，并在 Trace 中分别显示。
3. 任一 Agent 失败不会抹掉其他 Agent 的有效结果。
4. API 输出包含标准回答和机器可读执行轨迹。
